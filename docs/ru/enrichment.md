# Обогащение по открытым госисточникам

Лид из открытого поста — это анонимное «нужен бот для учёта, бюджет 50 тыс». Непонятно главное:
это живая компания или однодневка, какая у неё отрасль, есть ли у неё деньги и с кем говорить.

Ответ лежит в открытых государственных реестрах, куда пускают **без API-ключей, регистраций и оплаты**.

## Три источника

| Источник | Адрес | Что отдаёт | Скорость |
|---|---|---|---|
| **ЕГРЮЛ** | `egrul.nalog.ru` | юрлицо (полное и краткое), ИНН/ОГРН/КПП, дата регистрации, регион, **руководитель с должностью**, **дата прекращения** деятельности | ~2 с |
| **Реестр МСП** | `rmsp.nalog.ru` | категория (микро / малое / среднее), **ОКВЭД + расшифровка отрасли**, город, активность в реестре, лицензии, госконтракты | ~0,2 с |
| **«Работа России»** | `opendata.trudvsem.ru` | жив ли бизнес **сейчас**: сколько активных вакансий, последняя, **email работодателя** | 5–60 с |

Плюс ФНС `data.nalog.ru` — открытые наборы (реестр МСП целиком, среднесписочная численность, налоговый долг, массовые адреса, дисквалификации). Забираются выгрузкой, не по запросу.

## Как это работает

```
текст поста
   ↓ извлекаем якоря (ИНН/ОГРН по контрольной сумме, email, телефон, домен, @username, названия)
ЕГРЮЛ        → кто это, жив ли, кто руководитель
   ↓ ИНН/ОГРН
Реестр МСП   → отрасль, размер, город, лицензии, госконтракты
   ↓ ОГРН
trudvsem     → есть ли активность сейчас + рабочий email
   ↓
карточка бизнеса (схема wlp.enrich/v1)
```

## Почему ИНН проверяется по контрольной сумме

Любое 10-значное число в тексте — не обязательно ИНН: это может быть телефон, сумма, артикул.
Если отправлять такие числа в реестр, приходит чужой бизнес или пустота — и карточка врёт.

`inn_valid()` и `ogrn_valid()` считают контрольную сумму по алгоритму ФНС. Не прошло — якорь
не берётся. В `--text`-режиме это главная защита от ложных срабатываний.

## Использование

```bash
# внутри общего прогона — обогатить топ-N тёплых лидов
python warm_lead_parser.py ai-agents --enrich-top=3

# отдельно: по ИНН, названию или свободному тексту
python integrations/enrich.py --inn 7707083893
python integrations/enrich.py --name "Мастер-Ювелир"
python integrations/enrich.py --text "Нужен бот, ИНН 7707083893, бюджет 50 тыс"

# JSON для своей сборки
python integrations/enrich.py --inn 7707083893 --json

# проверка без сети
python integrations/enrich.py --selftest
```

## Что получается на выходе

Живой прогон 24.10.2026, пост в Telegram-канале:

```
- 🟢 ООО "ЭДЮСОН" · ИНН 7729779476
  - Деятельность по дополнительному профессиональному образованию · Г.Москва · с 14.08.2014
  - ГЕНЕРАЛЬНЫЙ ДИРЕКТОР: Новожилова Кристина Игоревна
```

По одному ИНН (`7707083893`): юрлицо, ФИО руководителя с должностью, регион,
107 активных вакансий и рабочий email — за один вызов, без ключей.

## Границы

- **Не везде есть за что зацепиться.** В Telegram-объявлениях и на части бирж заказчик
  не называет ни ИНН, ни компанию — тогда обогащение честно отвечает «не найден».
  Лучше всего работает там, где заказчик себя называет: сайты, HH, ЕИС, подписанные посты,
  входящая переписка.
- **Однофамильцы.** ЕГРЮЛ по названию отдаёт до 20 записей, среди них бывают ликвидированные.
  Модуль выбирает точное совпадение названия и предпочитает действующую запись; если в выдаче
  есть ликвидированные, это указывается в сигналах.
- **«Работа России» медленный** — 5–60 с на организацию. Флаг `--no-vacancies` отключает.
- **ЕГРЮЛ роняет серии запросов** без паузы. В коде пауза 1,0–1,2 с между вызовами.
- **Это не досье на человека.** Модуль берёт то, что государство публикует само: организацию,
  её руководителя как публичную должность, контакт, оставленный для деловой связи.

## Этика

Границы те же, что у парсера: только открытые реестры, никаких логинов, никакого обхода защиты.
Никакого массового сбора персональных данных — обогащается тот, кто сам опубликовал заказ и
указал, к какой организации относится. См. [`SAFETY_RAILS.md`](../../SAFETY_RAILS.md).
